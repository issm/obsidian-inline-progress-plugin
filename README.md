# Inline Progress

ノートの中の `[progress:: 10/12]` というインラインフィールドを、固定幅の進捗バーとして表示する Obsidian プラグインです。

個数で表す通常の進捗バーに加えて、完了した位置を指定する「歯抜け」の進捗バーも表せます。

## 使い方

ノートに次のように書きます。

```
- [ ] 通常の進捗 [progress:: 10/12]
- [ ] 歯抜けの進捗 [progress:: 1,3,5/12]
- [ ] 2番目だけ完了 [progress:: ,2/12]
- [ ] ラベルなし [progress:: 10/12; nolabel]
- [ ] 13〜26 の範囲の進捗 [progress:: 3/13-26]
- [ ] 13〜26 の範囲の歯抜け [progress:: 13,15,18/13-26]
- [ ] 分母が分からない [progress:: 5/?]
```

### 値の書式

`完了/総数`、`完了/開始-終了`、または `完了/?`（分母が不明）の形で書きます。

| 書式 | 意味 |
|---|---|
| `10/12` | 12個のうち、先頭から10個が完了 |
| `,2/12` | 12個のうち、2番目だけが完了 |
| `1,3,5/12` | 12個のうち、1・3・5番目が完了（歯抜け） |
| `3/13-26` | 13〜26（14個）のうち、先頭から3個が完了 |
| `13,15,18/13-26` | 13〜26（14個）のうち、13・15・18 が完了（歯抜け） |
| `5/?` | 分母が不明で、5個が完了 |

- 区切りのカンマが1つでも含まれていれば、位置の指定になります。含まれなければ個数の指定です。`2/12` は「先頭から2個」、`,2/12` は「2番目だけ」を表します。
- 位置は1始まりです。重複した位置は1つにまとめられます。
- `開始-終了` で範囲を指定すると、その範囲の区画数（両端を含む）が総数になります。`13-26` なら 14 個です。
  - 位置は、範囲の先頭から数えた番号ではなく、範囲内の値そのものを書きます。`13,15,18/13-26` は、範囲の中の 13・15・18 が完了です（範囲の先頭から数えると 1・3・6 番目）。
  - 個数指定の `3/13-26` は、範囲の先頭から3個（13・14・15）が完了です。
  - `/12` は `/1-12` と同じです。
  - 開始は 0 以上の整数です。
- 分母が不明なときは、`?` または `-` を書きます。範囲の片方が不明な場合も、分母不明として扱われます。次はすべて同じ意味です。
  - `5/?`、`5/-`
  - `5/13-?`、`5/13-`（範囲の終了が不明）
  - `5/?-26`、`5/-26`（範囲の開始が不明）
  - `5/?-?`、`5/-?`、`5/?-`
  - 分母が不明なときは、区画が分からないので、バーは塗らず、位置指定（`1,3,5/?`）でも位置の範囲は検査しません。完了数は、重複を除いた位置の個数（`3/??`）です。
- 先頭や末尾のカンマは無視されます。`,2/12` と `2,/12` は同じ意味です。
- 値の内側には空白を置けません。`1, 3/12` や `10 /12` は不正な値になります。`progress::` の直後の空白や、`;` の前後の空白は構いません。
- フィールド名の区切りはコロン2つ（`progress::`）です。

### オプション

値のうしろに `;` で区切って書きます。

| オプション | 意味 |
|---|---|
| `nolabel` | バーの右のラベルを表示しない |

```
[progress:: 10/12; nolabel]
```

### ラベル

バーの右に、完了した数と総数を `3/12` のように表示します。位置指定（`1,3,5/12`）の場合は、完了した位置の数（3個）が表示されます。範囲指定（`13,15,18/13-26`）の場合も、完了した数と範囲の区画数（`3/14`）で、範囲の開始や終了の値は表示しません。分母が不明なときは、`5/??` のように表示します。`nolabel` で消せます。

### 不正な値

次のような値は、バーに置き換えず、元のテキストのまま表示します。書き間違いに気づけるようにするためです。

- 個数が総数を超える（`13/12`、`15/13-26`）
- 位置が範囲外（`0,13/12`、`1,13/12`、`12,15/13-26`）
- 総数が 0（`1/0`）
- 開始が終了を超える範囲（`3/26-13`）
- 数字のない位置指定（`,/12`）
- 値の内側に空白がある（`1, 3/12`）
- 未知のオプション（`10/12; foo`）

## 表示

- 閲覧モードとライブプレビューで表示されます。ソースモードでは、元のテキストのまま表示されます。
- ライブプレビューでは、カーソルや選択範囲がフィールドに触れている間は、編集できるよう元のテキストが表示されます。
- インラインコードやコードブロックの中は、置き換えません。
- 全区画が完了したとき（`12/12` など）は、バーの塗りがテーマの「成功」の色（`--text-success`）になります。
- 区画の境目に、目盛り線が入ります。1区画の幅（バーの幅 ÷ 分母）が 4px 以上のときだけ表示し、4px 未満では表示しません。区画が細かいと目盛りが縞模様になって見づらいためです。既定の幅（`8em`、16px で 128px）では、分母が 32 までです。
  - 環境によっては、幅に応じた制御が使えず、分母が 33 以上のときに消える動きになります。

### 見た目の調整

バーの見た目は CSS 変数で変えられます。**Settings → Appearance → CSS snippets** に、次のような CSS スニペットを追加してください。

```css
.inline-progress {
	--inline-progress-width: 12em;   /* バーの幅（既定 8em） */
	--inline-progress-height: 0.4em; /* バーの太さ（既定 0.5em） */
	--inline-progress-margin: 0.6em; /* 左右の余白（既定 0.4em） */
	--inline-progress-tick-width: 2px; /* 目盛り線の太さ（既定 1px） */
	--inline-progress-tick-color: black; /* 目盛り線の色（既定 var(--background-primary)） */
	--inline-progress-tick-min-pitch: 3px; /* 目盛り線を表示する 1 区画の最小の幅（既定 4px） */
	--inline-progress-unknown-color: gray; /* 分母が不明なときの破線の色（既定 var(--text-faint)） */
}
```

色は、テーマの変数（塗りは `--interactive-accent`、完了時は `--text-success`、背景は `--background-modifier-border`、目盛り線は `--background-primary`）に従います。

目盛り線をなくしたい場合は、次のスニペットを追加します。

```css
.inline-progress-track::after {
	display: none;
}
```

## インストール

現在はコミュニティプラグインとしては公開していません。手動でインストールします。

1. `main.js`、`manifest.json`、`styles.css` を、Vault の `.obsidian/plugins/inline-progress/` にコピーします。
2. Obsidian を再読み込みします。
3. **Settings → Community plugins** で **Inline Progress** を有効にします。

## 開発

Node.js 18 以上が必要です。

```bash
npm install
npm run dev     # 変更を監視してビルド
npm run build   # 型チェックと本番ビルド
npm run lint    # ESLint
```

ソースは `src/` にあります。設計は [docs/design.md](docs/design.md)、設計上の判断の記録は [docs/adr/](docs/adr/) にあります。

## リリース

- `manifest.json` の `version` を上げ、`versions.json` に対応する最小の Obsidian バージョンを追加します。`npm version patch` などで、この2つをまとめて更新できます。
- GitHub のリリースを作ります。タグは `manifest.json` の `version` と完全に同じにします（先頭に `v` を付けません）。
- `manifest.json`、`main.js`、`styles.css` を、リリースにファイルとして添付します。
