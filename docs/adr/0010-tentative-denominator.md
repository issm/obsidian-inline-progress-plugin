# 0010: 分母の数字のうしろの `?` で、仮の分母を表す

- 状態: 採用
- 日付: 2026-10-24

## 状況

分母は分かっているが、まだ確定していないことがある。たとえば、全体の数が、見積もりや予定で、今後変わるかもしれない場合である。分母が不明な場合（[ADR 0009](0009-unknown-denominator.md)）とは違い、仮の数字でバーは描ける。ただ、確定した分母と見分けられるようにしたい。

## 決定

- 分母の数字のうしろに `?` を付けると、仮の分母とする。
  - `5/12?`
  - `5/13?-24`（範囲の開始が仮。13〜24 は12個）
  - `5/13-24?`（範囲の終了が仮）
  - `5/13?-24?`（どちらも仮）
- 値の扱い（塗り、位置の検査、ラベルの分母の計算）は、`?` が無いときと同じにする。たとえば `5/12?` は、`5/12` と同じ塗りで、`13/12?` は個数が分母を超えるので不正である。
- 違うのは見た目だけとする。
  - ラベルは、分母のうしろに `?` を付ける（`5/12?`、範囲なら `3/14?`）。
  - 塗りの色を、`--inline-progress-tentative-color`（既定 `--color-yellow`）にする。
  - 全区画が塗られていても（`12/12?`）、完了の緑にはしない。仮の分母は確定していないので、完了とは言えないため。
- 範囲の端のどちらかが不明（`?` だけ、または省略）のときは、分母不明（ADR 0009）が優先される。`13?-?` は、仮ではなく分母不明である。
- `12??` や `1?2` のように、数字の直後の1つの `?` 以外の書き方は不正とする。
- `aria-valuetext` に、ラベルと同じ文字列を入れて、仮であることを読み上げでも伝える。

## 検討した代替案

- 塗りの色に `--text-warning` を使う。Obsidian の既定では `--color-orange` に解決される。Obsidian Nord では `#d08770` となる。この決定の時点では、通常の塗りが `--interactive-accent`（`#bf616a`）で、よく似た赤みのある色のため区別しにくかった。`--color-yellow`（Nord では `#ebcb8b`）なら、はっきり区別できた。その後、通常の塗りを `--color-cyan` に変えた（[ADR 0005](0005-appearance-via-css-variables.md)）が、黄色は、緑（満了）とも青系（通常）とも区別できるので、そのままにした。
- 仮の分母が満了したら、緑にする。確定した分母と同じ扱いになり、「仮」を示す意味が薄れる。
- 仮の分母を超えた個数を許可する。分母を見直すきっかけになる、という利点はあるが、値の扱いが `?` の有無で変わり、規則が複雑になる。超えた場合は不正値として元のテキストが残るので、書き間違いに気づける。必要になれば、別の決定として扱う。
- 仮の分母を別のオプション（`; tentative`）で表す。分母の数字と離れ、どの端が仮か（範囲の開始か終了か）を表せない。

## 結果

- 見積もりの数字でも、進捗を描き、確定した分母と見分けられる。
- 分母に `?` を付けるか、`?` だけを書くかで、意味が分かれる（仮か不明か）。`5/12?` と `5/?` は別の意味である。
- 仮の分母を超える進捗は、不正値になる。分母を直すか、`?` を外して確定する必要がある。
- 範囲の開始と終了の仮は、見た目では区別しない（どちらが仮でも、同じ表示になる）。
- 満了でも黄色のまま、という扱いは、`is-complete` と `is-tentative` のCSSの順序で決まっている。緑にしたい場合は、CSS スニペットで上書きできる。
