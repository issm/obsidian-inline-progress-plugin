# 0001: 位置指定はカンマの有無で個数指定と区別する

- 状態: 採用
- 日付: 2026-10-24

## 状況

`[progress:: 2/12]` のように、カンマを含まない値は「先頭から2個が完了」とも「2番目だけが完了」とも読める。個数で表す通常の進捗バーと、完了した位置を指定する歯抜けの進捗バー（`1,3,5/12`）の両方を、曖昧さなく書けるようにしたい。

## 決定

- 区切りのカンマが値の中に1つでも含まれていれば「位置の集合」、含まれなければ「個数」とする。
- 位置指定では、空の要素（先頭・末尾・連続したカンマ）を無視する。したがって `,2/12` と `2,/12` は、どちらも「2番目だけ」を表す。
- 数字が1つもない `,/12` は不正な値とする。

| 書式 | 意味 |
|---|---|
| `2/12` | 先頭から2個 |
| `,2/12` | 2番目だけ |
| `1,3,5/12` | 1・3・5番目 |

## 検討した代替案

- 位置指定の目印として、括弧や接頭辞を使う（`{2}/12`、`#2/12`）。目立つが、`1,3,5/12` と書式が揃わなくなる。
- 単独の数字（`5/12`）を位置として扱う。個数指定を書けなくなる。

## 結果

- 規則が単純で、パーサーも `split(',')` して空要素を捨てるだけで済む。
- `2/12` と `,2/12` は1文字違いで、書き忘れや見落としで別の意味になる。ただし表示が「先頭から塗られたバー」から「1区画だけのバー」に変わるので、見た目で気づける。
- 範囲記法（`1-3,7/12`）は、この規則と矛盾せずに後から足せる。
